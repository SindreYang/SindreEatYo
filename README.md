# 吃哟咯（SindreEatYo）

药品提醒 App「吃哟咯」，使用 React Native + TypeScript + Expo 实现。当前先完成 Android，iOS 保留后续整体构建。

## 已实现

- 药品名称与备注管理
- 按间隔或固定时间提醒，固定时间使用小时/分钟滚轮，可精确到每一分钟
- 每天/每周/自定义重复字段（第一版 UI 已保留扩展位）
- 到点后每隔 1 分钟响铃并振动，直到确认已吃药
- 通知到达后进入待确认状态
- “确认已吃药”；未确认记录不会自动停止提醒
- 本地持久化
- 简洁中文界面、安全区布局、可点击的“添加/修改/删除”入口
- Android 原生 `AlarmManager.setAlarmClock`、通知渠道、系统闹钟铃声、振动、锁屏和开机恢复
- 到点由原生广播接收器直接播放系统当前闹钟声并振动，不依赖打开 App；设置页可检查电池优化和后台运行限制
- 提醒计划会启动可关闭的 Android 前台服务；用户可以退出 App 主界面，前台服务继续等待并处理提醒，系统会显示一条后台提醒通知
- Android 10+ 后台到点时通过独立的高优先级全屏通知进入锁屏提醒页；前台服务只负责保活通知，不从后台直接启动页面，避免触发 Android 15 的后台启动限制
- 全屏提醒页和通知本身都提供“确认已吃药”；确认后原生立即停止响铃/振动，并把确认结果同步回今日页，不要求先跳转到主页面
- 今日页以“现在需要确认”为唯一主任务，确认按钮独占整行；药品页负责添加、修改和删除，设置页负责权限、测试和日志
- 今日页会列出当天全部计划：未确认、接下来和已确认，并显示距离提醒时间；确认结果从原生锁屏提醒页/通知操作同步回来
- 每次原生闹钟广播都会滚动安排下一次提醒，开机后会从本地记录恢复过期计划，不受固定预排窗口限制
- 原生服务保留最近提醒事件历史，导出调试日志可用于定位广播、通知、铃声、振动和全屏入口是否执行
- 闹钟声音以手机系统闹钟 URI 的 MediaPlayer 为主路径，RingtoneManager 为兜底，并记录闹钟音量、响铃模式和实际播放路径
- 关闭 App 主界面不会取消 AlarmManager 计划；前台服务只在到点时启动并负责响铃、振动和提醒页，系统计划不依赖 React Native 页面常驻
- 设置页可“立即测试响铃和振动”，并可导出不含药品名称和备注的调试日志
- 原生闹钟模块通过 Expo 配置插件注入，执行 `expo prebuild` 后不会丢失

## 本地运行

```bash
npm install
npx expo start
```

Windows 可以直接开发和运行 Android；iOS 需要 macOS + Xcode，或交给 GitHub Actions 的 macOS Runner 构建。

## GitHub Actions

- `.github/workflows/android.yml`：Ubuntu Runner 构建可独立启动的 Android Release APK（内置 JS bundle）
- `.github/workflows/ios.yml`：仅手动触发的 iOS 构建占位流程

Android 提醒优先使用原生闹钟、前台服务和通知链路，使用高优先级通知、手机系统闹钟音频、振动、锁屏可见、全屏提醒入口和开机恢复；设置页会读取实际的通知、精确闹钟、全屏提醒、电池优化和前台服务状态。即使通知被划掉或错过，App 内仍保留“待确认吃药”。Android 不允许应用阻止用户主动强制停止或厂商极端省电策略，因此设置页会引导用户允许后台运行、自启动和“不限制”耗电。
设置页只在权限未完成时显示操作按钮；已经自动开启的权限只显示状态，避免反复提示“开启闹钟权限”。

## 导出调试日志

如果真机上没有响铃、没有通知、状态显示不正确：

1. 打开“设置”。
2. 点击“立即测试响铃和振动”。
3. 返回设置，点击“导出调试日志”。
4. 在系统分享面板中发送日志文件内容给开发者。

日志只记录权限状态、调度数量、原生接收、铃声/振动触发、后台限制状态、测试操作和错误信息，不记录药品名称、备注或提醒内容。

真机 iOS 发布包仍需要 Apple Developer 证书、Provisioning Profile，以及 GitHub Secrets。普通系统通知可能被用户划掉，App 内“待确认”状态不会被清除；若需要无视静音/勿扰模式的强提醒，需要另行申请平台权限。
